# Трекер расходов

Личный учёт расходов и доходов в виде веб-приложения (PWA), которое ставится на экран «Домой» айфона и работает как обычное приложение — в том числе без интернета.

- **Без сервера.** Данные хранятся на устройстве (IndexedDB — встроенная база браузера).
- **Синхронизация телефона и компьютера (по желанию)** — через твой приватный репозиторий на GitHub, тоже бесплатно.
- **Бесплатный хостинг** на GitHub Pages, деплой автоматический при каждом изменении в `main`.
- **Только рубли**, суммы с копейками.

## Возможности

- Расходы и доходы: сумма, категория, дата, комментарий. Правка и удаление (с кнопкой «Вернуть»).
- Список по дням с итогами, переключение месяцев, фильтр по категории.
- Статистика: итоги месяца, сравнение с тем же периодом прошлого месяца, средний расход в день, разбивка по категориям, график по дням, график и таблица за 6 месяцев.
- Регулярные платежи (подписки, аренда, зарплата): раз в месяц или раз в год. Записываются в операции сами, когда открываешь приложение; пропущенные дни догоняются, дублей не бывает.
- Свои категории с эмодзи.
- Резервная копия в JSON и восстановление из неё, выгрузка в CSV для Excel / Numbers.
- Синхронизация между устройствами через приватный GitHub-репозиторий, подключение второго устройства по QR-коду.
- PIN-код на вход и разблокировка по Face ID / Touch ID.
- Светлая и тёмная тема (по настройке айфона), офлайн-режим.

## Запуск на GitHub Pages (один раз)

1. Репозиторий должен быть **публичным** — на бесплатном тарифе GitHub Pages работает только для публичных репо. Публичен только код; твои расходы в репозиторий не попадают.
2. Открой **Settings → Pages** и в поле **Source** выбери **GitHub Actions**.
3. Влей изменения в ветку `main` (или запусти вручную: **Actions → Tests & Deploy → Run workflow**).
4. Дождись зелёной галочки во вкладке **Actions** (1–2 минуты).
5. Сайт будет доступен по адресу: **https://ermin372.github.io/treker_rashodov/**

Если деплой упал на шаге `configure-pages` — значит, не сделан пункт 2.

## Установка на айфон

1. Открой ссылку выше **в Safari** (не в Chrome и не во встроенном браузере Telegram).
2. Нажми «Поделиться» (квадрат со стрелкой вверх) → **«На экран „Домой“»** → «Добавить».
3. Запускай приложение только с иконки.

> ⚠️ У Safari и у приложения с экрана «Домой» **разные хранилища**. Расходы, добавленные в Safari, не появятся в установленном приложении, и наоборот.

## Синхронизация телефона и компьютера

Данные лежат в файле `rashody.json` в **твоём приватном** репозитории. Каждое устройство само забирает оттуда изменения и отправляет свои: при открытии, через пару секунд после правки и раз в минуту, пока приложение открыто. Без интернета всё работает как раньше и догоняется, когда связь появится. Каждое изменение — отдельный коммит, так что история репозитория служит ещё и бесплатным бэкапом.

**Настройка (один раз, удобнее с компьютера):**

1. Создай **приватный** репозиторий, например `treker-data`: https://github.com/new — выбери **Private** (публичный приложение не примет) и поставь галочку **Add a README file**.
2. Создай fine-grained токен: https://github.com/settings/personal-access-tokens/new
   - Repository access → **Only select repositories** → `treker-data`;
   - в разрешениях репозитория: **Contents → Read and write** (больше ничего не нужно);
   - срок действия — максимальный из доступных.
3. В трекере: **Настройки → Включить синхронизацию** → впиши `твой-логин/treker-data` и токен → «Готово». Уже внесённые данные тоже уедут в репозиторий.
4. На айфоне открой трекер **с иконки** → Настройки → Включить синхронизацию → **«Сканировать QR»** и наведи камеру на код из «Подключить другое устройство» на компьютере. Можно и скопировать ключ, а потом вставить его.

**Как решаются конфликты.** У каждой записи есть время изменения, при конфликте побеждает более свежая версия. Удаление хранится как «надгробие», поэтому удалённое на одном устройстве не воскресает с другого. Автоплатежи из регулярных у всех устройств получают одинаковый id, так что дублей не бывает. Если два устройства пишут одновременно, GitHub отклоняет устаревшую запись, и приложение перечитывает файл и сливает изменения заново.

**Безопасность.**
- Токен хранится только на твоих устройствах и даёт доступ к одному репозиторию и только к файлам. Если он утёк, удали его в GitHub → Settings → Developer settings → Personal access tokens и создай новый.
- Все сайты GitHub Pages одного аккаунта живут на одном домене `ermin372.github.io`, поэтому не публикуй там чужой или непроверенный код: он технически сможет прочитать данные трекера.
- «Удалить все данные» чистит только текущее устройство и отключает на нём синхронизацию; данные в репозитории остаются.

## PIN-код и Face ID

**Настройки → Защита → Поставить PIN-код.** После этого приложение спрашивает PIN:
- при каждом запуске;
- после сворачивания — сразу, через 1, 5 или 15 минут, на выбор;
- после 5 минут бездействия при открытом приложении.

Пока приложение свёрнуто, суммы скрыты, чтобы не попасть в превью переключателя приложений.

- **Face ID / Touch ID** включается переключателем в том же разделе. Айфон сохранит ключ входа (passkey) в «Пароли». На экране блокировки нажми «Войти по Face ID», а если не сработало — введи PIN.
- **PIN у каждого устройства свой** и в синхронизацию не попадает. Хранится только его хэш (PBKDF2 с солью), сам PIN нигде не записан.
- **После 5 неверных попыток** ввод замораживается на 30 секунд, дальше пауза удваивается, максимум до часа. Перезапуск паузу не сбрасывает.
- **Забыл PIN:** «Забыли PIN?» → данные **этого устройства** стираются. Обойти PIN без потери данных нельзя, иначе любой, кто взял телефон, мог бы это сделать. С синхронизацией данные вернутся из GitHub после повторного подключения ключом с другого устройства; без неё — только из файла резервной копии.
- **Это защита от человека с твоим разблокированным телефоном, а не шифрование.** Данные на устройстве не зашифрованы: тот, у кого есть доступ к компьютеру и инструменты разработчика браузера, сможет их прочитать.

## Резервные копии — важно

Без синхронизации данные живут только на одном телефоне. Если удалить иконку с экрана «Домой», сбросить айфон или очистить данные сайтов — данные пропадут. С синхронизацией копия всегда лежит в репозитории, а напоминание о бэкапе отключается.

- **Настройки → Сохранить резервную копию** — откроется меню «Поделиться», сохрани файл в «Файлы» / iCloud Drive или отправь себе.
- Приложение само напомнит, если копии не было больше месяца.
- **Настройки → Восстановить из копии** — заменяет текущие данные данными из файла (так же переносятся данные на новый телефон).

## Обновления

После каждого деплоя в `main` приложение на айфоне обновится само при следующем запуске с интернетом (иногда нужно открыть его дважды). Версия сборки видна внизу экрана «Настройки».

## Локальная разработка

```bash
# запустить локально (без офлайн-кэша, чтобы правки сразу были видны)
python3 -m http.server 8080 -d app
# открыть http://localhost:8080

# тесты логики и синхронизации (деньги, даты, регулярные платежи, слияние, конфликты)
npm test
```

Сборки нет — это чистые HTML/CSS/JS-модули без зависимостей.

```
app/
  index.html            разметка и мета-теги для iOS
  manifest.webmanifest  описание PWA (имя, иконки)
  sw.js                 service worker: офлайн-кэш
  css/style.css         стили, светлая и тёмная тема
  js/app.js             интерфейс
  js/logic.js           чистая логика (покрыта тестами)
  js/db.js              работа с IndexedDB
  js/charts.js          SVG-графики
  js/sync.js            синхронизация через GitHub API
  js/lock.js            PIN-код (хэш PBKDF2) и Face ID через passkey
  vendor/               QR-код: генератор и сканер (сторонние, см. vendor/README.md)
  icons/                иконки приложения
tests/                  тесты (node --test)
.github/workflows/pages.yml  тесты + деплой на GitHub Pages
```

## Ограничения

- Синхронизация не мгновенная: изменения с другого устройства приходят в течение минуты (или сразу по кнопке «Синхронизировать сейчас»).
- Только одна валюта (₽).
- Регулярные платежи записываются, когда приложение открыто: если не открывать его месяц, все пропущенные платежи появятся разом при следующем запуске.
